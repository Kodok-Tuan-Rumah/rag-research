# An earlier version of this file attributed four test failures to a
# "numpy 2.5.3 / Python 3.14 incompatibility". That was wrong, and the numpy
# error message is misleading. Real cause, reproduced in isolation:
#
#   unittest.mock.patch.dict(sys.modules, ...) snapshots sys.modules and
#   restores it wholesale on exit, so any module first imported *inside* the
#   block is evicted. numpy.fft._pocketfft_umath is a C extension, and CPython
#   forbids initialising the same extension twice in one process — hence
#   "ImportError: cannot load module more than once per process". sklearn and
#   transformers both pull numpy.fft in through the patched import, which is why
#   a test that passed alone failed inside the full suite.
#
# Fix: pre-import numpy.fft above the patch.dict block so it lands in the
# snapshot. Both affected files now do this.
#
# This is a test-harness defect, NOT a numpy or Python 3.14 defect, and is
# unrelated to src/_compat.py (which handles a separate protobuf upb problem).
